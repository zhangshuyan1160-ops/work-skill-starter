# 日常工作 Skill 整合草案

这套草案覆盖通用办公、科研学习和技术工作。根据 2026 年 10 月 10 日对 8 个 GitHub 仓库、26 个候选 Skill 的比较，先实现 6 个独立的中文工作流程。优先补足跨步骤的衔接，文档生成、专业统计、绘图和具体框架操作由当前环境已有能力承担。

当前版本：可试用的初始草案。格式校验和实际任务效果分开记录；来源审查不等于上游脚本、外部服务或这些新流程已通过运行验证。

## 三类工作如何衔接

| 方向 | 日常流程 | 当前草案 |
|---|---|---|
| 通用办公 | 会议记录 → 明确决定与行动项 → 汇总实际进度 → 周报 | meeting-action-brief、weekly-progress-brief |
| 科研学习 | 明确问题 → 阅读与核对证据 → 理解差异 → 练习与迁移 | evidence-research-brief、concept-practice |
| 技术工作 | 数据问题 → 口径核对与计算 → 结果简报；代码故障 → 假设与复现 → 修复与验证 | data-decision-brief、debug-evidence-loop |

各环节只在当前请求需要时执行。例如只要会议纪要就结束在纪要；只要论文摘要就不自动安排学习课程；只要数据指标就不展开完整报告。

## 六个 Skill

| Skill | 输入与输出 | 使用示例 |
|---|---|---|
| [meeting-action-brief](skills/meeting-action-brief/SKILL.md) | 记录或转写 → 决定、行动项、待确认信息与来源 | 把组会记录转成行动项，未确定的负责人和日期明确标出。 |
| [weekly-progress-brief](skills/weekly-progress-brief/SKILL.md) | 任务、会议、提交记录 → 按事实状态整理的周报 | 根据这些记录写给导师的周报，区分完成、待验证与阻塞。 |
| [evidence-research-brief](skills/evidence-research-brief/SKILL.md) | 调研问题、论文或文档 → 有证据与适用条件的结论 | 比较三篇论文的实验条件，判断哪个值得先复现。 |
| [concept-practice](skills/concept-practice/SKILL.md) | 概念或学习材料 → 解释、练习、反馈与迁移 | 讲解注意力机制，再用两道题检查我的理解。 |
| [data-decision-brief](skills/data-decision-brief/SKILL.md) | 分析问题及数据 → 经口径核对的数字和解释 | 分析转化率下降，先检查分母、渠道和统计周期。 |
| [debug-evidence-loop](skills/debug-evidence-loop/SKILL.md) | 报错、代码及环境 → 原因证据、修复与验证结果 | 定位本地正常但 CI 失败的问题，修复后报告实际检查结果。 |

这些 Skill 只需要宿主具备任务所需的基础工具。会议信息和学习练习可直接处理文本；联网调研需要可用检索；真实数据计算和代码修复需要相应文件及执行环境。没有数据库或平台连接器时可使用用户提供的文件，不会虚构访问成功。

## 具体优化了什么

### 办公

会议纪要明确分开建议、决定与承诺，缺少负责人或日期也可以先交付。周报对同一交付物去重，保留已提交、已合并、已上线的区别，不把讨论次数当成果。平台同步与消息发送随用户请求执行，不从“生成纪要”推导出分发权限。

### 科研学习

调研使用“主张、来源、位置、读取范围、条件、支持程度”的证据记录。摘要不能冒充全文，DOI 存在不能代替主张核对。概念练习是本项目新增的组合环节：让阅读产生可观察的练习表现；没有真实回答就不宣布已经掌握。正式系统综述、论文投稿和专业实验审查仍按其专门流程进行。

### 技术工作

数据简报先固定观察单位、统计周期、分子分母，再计算和解释。调试把证据、假设、修改和原始故障验证连起来；检查范围决定成功声明的范围。有新变更才重新验证，简单修改不机械增加完整测试流程。

## 与现有专业能力配合

这些流程可与文档、PDF、演示文稿、电子表格、学术研究、统计分析、Python 和机器学习等专业能力配合。根据使用者环境中实际可用的工具选择，不要求安装某个固定集合。

- Office 文件读写继续使用现有文档技能。
- 论文精读、检索、评审与写作按任务选用现有学术技能；新调研入口服务于跨资料的具体问题。
- 专业数据分析使用现有统计和绘图能力；新入口负责问题、口径、证据与报告的衔接。
- Python、模型训练及框架实现保留专门技能；新调试入口关注问题原因和实际验证。

避免为每个来源再安装同名或功能等价的 Skill。实际使用时，只有任务需要某项专业能力才加载它，不预先加载整个集合。

## 验证与下一步

格式检查结果保存在 [validation.json](validation.json)。另有 [18 个行为评估用例](eval/cases.json)，覆盖正常任务、缺失信息和不应触发的请求；目前这些用例是验收设计，尚未作为独立模型测试运行。

验证优化效果时，对同一输入比较原版、当前草案及无 Skill 三种输出，检查事实与数字错误、额外操作、必要追问、任务完成度和篇幅。优先用一份真实会议记录、一组周报材料、一篇论文和一个真实技术问题试用。记录失败后再做针对性修改，不把格式通过当作效果提升证据。

## 本地试用与发布

每个文件夹均可独立阅读。未安装时，可以在请求中提供对应 SKILL.md 的路径，要求按它处理给定材料。要正式安装到某个宿主时，使用该宿主当前支持的 Skill 安装方式；目录组织与使用示例参考 [OpenAI 官方文档](https://learn.chatgpt.com/docs/build-skills)。本项目不依赖特定的全局安装路径。

每个 Skill 目录可单独分发；整个集合包含 skills、README、LICENSE、候选目录、来源快照、验证记录及 eval。下载仓库不会自动安装任何技能，也不会改变已有工具配置。

本项目新写的中文指令与文档采用 MIT 许可证。上游文件仍受各自许可约束：本包不附带上游 Skill 正文、脚本或资产，不对上游材料重新授权。尤其不能将 anthropics/skills 的部分 source-available 文档技能当作 Apache 2.0 材料打包；具体依据保存在来源快照中。
