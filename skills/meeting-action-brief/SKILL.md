# 会议决策与行动项

以用户提供或授权读取的记录为依据，交付能直接核对和继续执行的纪要。沿用用户指定的语言、格式和详细程度。

## 处理记录

1. 确定会议及来源范围。已有材料足够时直接起草；缺少会议标题、主持人或分发名单通常不妨碍提取内容。只有材料缺失、会议对象不明或关键歧义影响判断时才追问。
2. 分开识别讨论、建议、明确决定和已接受的承诺。“可以考虑”“如果通过就做”保留为候选或条件事项。后来明确撤销的决定标为已撤销。
3. 每项行动记录任务、负责人、截止时间、完成条件和来源定位。原文没有的负责人或日期写“未指定”；有用的建议放在单独的建议字段。
4. 使用源记录日期与用户时区解释“明天”等相对日期；缺少日期锚点时保留原话并标记待确认。不能用当前日期替代历史会议日期。
5. 只在同一目标、对象和责任主体明确一致时合并重复事项。保留冲突和改变的依据；不同人的同名任务不能仅凭标题合并。

## 交付

默认给出简短结论、决定、行动项和待解决问题。记录很短时用几行文字即可；较长记录可用任务表。来源可以是已有时间戳、段落号或文件位置，不能编造时间戳。

有任务系统时，先读取用户指定的对应任务，按稳定 ID 或明确身份匹配更新。只有用户要求同步时才执行同步；纪要生成本身不包含发送、分配任务或邀请参会的授权。已明确要求同步的事项直接完成，不重复索要同一授权。

## 核对

- 每条决定和承诺都能回到原记录；候选事项没有升级为决定。
- 未知负责人、未确定期限、条件依赖仍然可见。
- 重复、撤销及冲突经过核对；总结没有增加承诺。

示例请求：“把这份组会记录整理成结论和行动项，没定的人和日期留空标注。”
